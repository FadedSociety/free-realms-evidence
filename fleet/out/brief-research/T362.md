# T362: Vendor shop: the 66/42 window must list the NPC's items with coin prices (native finding)

**Status at tip:** Not started as a client-mapped change, but the brief's premise is probably wrong. `66/42` is hard-wired to the Station Cash merchant mode in the client, so a coin-priced list cannot be opened through it. Coin merchant lists have a separate packet (165/10). I did not run the brief's `git apply` step; this was a read-only check.

**Current anchors:**
- `gameplay/npc.rs:1199` `merchant_packet` writes item id, purchase and sell prices into the first three dwords, zeros the rest (`repo:prototype/osfr-tools/src/gameplay/npc.rs:1199-1231`). The call site is `npc.rs:554-566`.
- `npc_interaction.rs:1300-1396` holds `MerchantEntryV2`, `MerchantListV2` and the 66/42 encoder and decoder. Layout: header, initial dword, six group dwords, count, then 38-byte entries (six dwords, bool, three dwords, bool).
- Shop label: `SHOP_STRING_ID = 432156` at `npc_interaction.rs:50`, documented as the reused generic "Interact" label. `opening_world.rs:91` also uses 432156 for non-NPC actors.
- The brief's `00b29cd0` is the entry reader (`ReadRecordDwordsAndFlags`). Its pseudocode writes +0x08, +0x10, +0x14, +0x18, +0x1c, +0x20 (six dwords), byte +0x24, dword +0x0c, dwords +0x28 and +0x2c, byte +0x30. This matches the Rust entry shape (`client fn 0x00b29cd0`).

**Client evidence:**
- `00b48a10` (66 dispatch), case 0x2a, calls `00b40a60`, stores the merchant GUID pair (`local_8b8[6]`, `[7]`, `[3]`) into manager +0x3e8f0 / +0x3e8f4 / +0x3e8f8, then builds the rows and calls `NpcMerchantV2:Show` with the constant string 018211d0 = "StationCash". There is no branch on mode. Every 66/42 window is therefore Station Cash (`client fn 0x00b48a10`, label strings list `018211d0=StationCash`).
- Rows go to the `BaseClient.InGamePurchase.MerchantSellBundles` datasource through `009a5270` ("RefreshMerchantSellBundles"), not `MerchantBuyInventoryData`.
- `ScriptsBase.lua:53871-53876`: StationCash mode calls `SetMerchantTimer` with the time value. This is the "Time Left" source. Which argument carries it is (unverified).
- `ScriptsBase.lua:54070-54080`: StationCash rows read `MerchantSellSC_DS` columns (ItemId 0, Price 5, MembersOnlyPrice, MaxPurchasable, QuantityAvailable, IsOnSale, SalePrice; `ScriptsBase.lua:2516-2552`).
- `ScriptsBase.lua:54010-54014`: `BuyItem` sends `isStationCash=1` in StationCash mode.
- `ScriptsBase.lua:53898-53910`: CoinStore mode uses `MerchantSell_DS` (`ScriptsBase.lua:3191-3225`, Price column 27). That is the coin window. Nothing in the 66/42 handler opens it.
- Coin merchant list: packet 165/10, `CoinStoreMerchantListPacket` (ctor `00c6ef90`), handler `HandleCoinStoreMerchantList` `00c78fb0` (`client_sql fn 00c78fb0`). Its notes are in `notes/Build Guides/Gameplay/Coin Store and Purchases.md:2042`. Its body fields are not yet decoded. The repo has no 165/10 sender (grep found none).
- Locale: 427314 "regular price", 427315 "member price", 430204 "Buy" (from `NpcMerchantV2` init, `ScriptsBase.lua:53835-53837`). I did not check 432156's text.

**Reference implementations:**
- Sanctuary (`refs:Sanctuary-main-20261019/src/Sanctuary.Game/Interactions/MerchantInteraction.cs:25-71`): for a coin merchant it sends the item-definition payload, then a `CoinStoreMerchantListPacket` (165/10) built from each entry. It sets the coin price from `definition.Cost` or the member price and skips entries with no client definition. Station Cash merchants use the separate 66/42 `InGamePurchaseMerchantListPacket`.
- So the community design uses two packets: 66/42 for SC, 165/10 for coins. The brief's plan of putting coin prices into 66/42 would fight the client.

**Risks and corrections:**
- The brief's core claim, "the 66/42 window must list items with coin prices", conflicts with `00b48a10` case 0x2a, which always opens StationCash. Items in that window will show SC prices and a timer, and buying sends the SC flag. Fixing the rows alone will not produce coin buys.
- A correct coin path needs a 165/10 encoder with the layout decoded from `00c78fb0` and its callees. That is a new packet family and a new coin-shop send, not a fill-in in `merchant_packet`. Roosey's 66/42 output should not be changed to fake coin prices.
- The prior 66/42 notes say the first three entry dwords are "item/purchase/sell by convention (R)" (`notes/Autopilot/F248.md:99-105`). The field table above suggests they are not verified semantics. Two of the nested-record dwords (the GUID pair) are used by 66/43.
- Hub growth: `gameplay/npc.rs` is near its cap. A 165/10 path should go in `coin_shop.rs` and the gateway routing.
- Lead-only areas: none directly touched, but `gateway.rs` routing for 165/10 is in the hub set.
- Brief hygiene: the attempt history is repeated and the patch names differ between paragraphs (`T362-a1`, `T362-opus`, `T362-a3`). The brief also says prices "from stores.json", but the 66/42 window reads `CoinShop`/`stores.json` through `NpcInteraction::load` (`notes/Autopilot/F248.md:259`).
