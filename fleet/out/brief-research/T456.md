**Client evidence:**
- **Record reader 00912cf0** (`ReadRecordWithBlobsAndFloats`), read in order from the pseudocode:
  1. u32 +0x00 id
  2. u8 (bool) +0x04. The getter's col 1 passes it to FUN_0098deb0, which picks one of two strings. Confirms it is the sex/gender column.
  3. u32 +0x08 = getter col 2 (formatted dword). This is the icon column, so species_id is wrong here.
  4. 4 × f32 at +0x20, +0x24, +0x28, +0x2c (NaN flags)
  5. u8 +0x30 members-only (getter col 8)
  6. count + rows into +0x34 (FUN_008fcdb0, which calls helpers 008f64e0 and 008ce1a0)
  7. count + u32s into +0xbc (FUN_008db130)
  8. count + rows into +0xe4 (FUN_008fc8c0, which calls 008e8ec0 and 008cdfb0)
  9. string (count + bytes), the name (getter col 0 via FUN_0097c5c0, the "PetName" template)
  10. u32 +0x1c (no getter column)
  11. u32 +0x100 (getter col 10 = FUN_00796170, a uint-key hash lookup)
  12. string, second block. Whether it lands at +0x108 or +0x10c is unverified.
  13. u32 +0xfc = getter col 9, image set
  14. u8 +0x104 = col 11, vanity bool
  15. u32 +0x118 = col 12, attachment group
  16. u8 +0x11c = col 13, tutorial bool
  17. 4 × u32 at +0x88..+0x94 (favourites), then 8 × u32 at +0x98..+0xb4 (utilities)
- **Getter FUN_00ccc680** (`PetListDataSource`, label record; the brief's "sub_CCC680" is this address; vtable 0x01838f64 unverified): col 10 reads +0x100. If that is 0, it reads the u32 at **+0x10c** as a C-string key (FUN_007961d0, `HashTableFindByCString700`). So the string is a hash key for the tint value, not a texture loader.
- **(a) +0x1c:** the getter never reads +0x1c, so the "fallback name text id" role is unverified. The Sanctuary order (Name then NameId) supports it (refs below).
- **(b) the string:** the getter only uses it as a hash key for tint (col 10). The wire position is directly after the tint id, which matches Sanctuary's `TextureAlias` at that point. My read: it is a tint alias key (R), not a texture path.
- **(c) +0x04:** confirmed as the sex column by the getter (col 1). Whether Models.txt GENDER is the value source is unverified (R).
- **Trick rows:** the row helpers read a u32 key per element. The trailing 8 u32 + u8 are read inside 008ce1a0 and 008cdfb0, which I did not read. The 37-byte and 12-byte row sizes come from Pets.md:111, 113 (unverified here).
- **00b5aea0** (list reader): count, then per entry a u32 key (stored at node +0x124) and one record via 00912cf0.
- **00b5fb30** (`DispatchPetActionRecord`): tests `+0x10 == 2` on a pet **action** record, not a trick row. The brief's "toy flag, 2 means toy action, 00b5fb30" is therefore a mis-attribution. Pets.md:127 is the source for the trick slot-4 claim (unverified).
- **00b55730** (`net.pet` reader): reads an 8-byte pair, then a length-prefixed string and a u8 accept flag (Pets.md:129).
