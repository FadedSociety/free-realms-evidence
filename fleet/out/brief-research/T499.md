**Risks and corrections:**
1. **AddNpc is per viewer in the fork.** Brief says "AddNpc is shared across viewers, leave 0." Lxzxrus sets the field per player (Player.cs:554, QuestManager.cs:440). The brief's choice may still be right, but it contradicts the fork. The native check should decide between 35/10-only and AddNpc-field-plus-35/10. The fork also uses remove-then-re-add to refresh a visible NPC (QuestManager.cs:437-441). The brief's refresh (35/10 or 35/11 with no re-add) is unproven on the client.
2. **Wrong test entry point.** Movement NPC visibility does not run through `Gameplay::handle_in_world`. `handle_in_world` (gameplay.rs:2169-2181) never calls `update_npc_visibility`. Movement uses gateway.rs:1591-1601. The test "through handle_in_world movement" would see no 35/2. Use `on_location` + `update_npc_visibility`, or the gateway harness.
3. **Batch order on the shared path.** The gateway pass appends `field.initialization(guid)` for `wanted - known` (osfr-gateway.rs:3291-3297) after the `shared_npc_view` packets. A marker for a passive NPC must come after its 35/2, which is in `packets`, not after the initialization batch. Check ordering in the test.
4. **No quest-NPC set exists.** Nothing builds the giver/turn-in/talk-target set. Talk targets are `ObjectiveKind::TalkToNpc` (quest_engine.rs:283, :610; matched at :1901). The builder must add it.
5. **Revision resets on rebind.** `bind_npc_quest_catalogue` (npc_quests.rs:12-58) builds a new engine via `from_split_content`. The new engine starts at revision 0, so a stored session revision can match by accident. Store the revision with the engine identity, or reset the session marker state on rebind.
6. **`set_eligibility` is a plain setter** (quest_engine.rs:1228-1230). `CharacterEligibility` derives `PartialEq` (:262), so the "bump when changed" rule is implementable. `QuestEngine` (:738) derives only Clone and Debug. `refresh_npc_quest_eligibility` (npc_quests.rs:140-143) is the only caller.
7. **Offered status hides markers.** `offer_denial` (quest_engine.rs:1653-1695) denies quests in `Offered`, so a giver loses its '!' while the 49/1 dialog is open. Expected, but the test should know it.
8. **Extras need content_key.** `content_keys` gets legacy rows (world.rs:308) and extras only when `content_key` is set (world.rs:362-363). Hasti (`npc_spawns_extra.json:27052`) must have a content key, or it gets no marker. Unverified whether it does.
9. **Lead-only and hub areas.** Session fields and teardown (osfr-gateway.rs:1962-1965) are off-limits by rule 16. A new session revision field needs init and reset there, which conflicts with that rule. Hubs: gameplay.rs (5,475 lines), osfr-gateway.rs (4,671), gateway.rs (2,232). Each gets at most +40.
10. **Brief's test file** `tests/quest_markers.rs` does not exist yet. Gates named in the brief exist: `tests/npc_greetings_*.rs`, `multiplayer.rs`, `playtest_gateway_smoke.rs`.
