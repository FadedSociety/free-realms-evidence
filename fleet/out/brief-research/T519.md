**Client evidence (client_sql):**
- **Request 156/2, `00bd3ff0`** (ECX = manager, guid halves in arg1/arg2, provider string arg3). Returns early if the guid is already in the pending map (hash `lo^hi`, map at +0x2c). Skips when guid == (`DAT_01beaa20`, `DAT_01beaa24`); meaning of the sentinel unverified. It inserts the pending entry (`00bd33d0`), builds the request via `00bd3230` (`008a23f0(2)`), and sends only if `[[obj+4]+0x280] != 0` (`00bd36c0`). If that flag is 0, the entry stays pending with no send (R, worth testing).
- **Providers the client sends:** `00bd4300` "TcgPortrait", `00bd4350` "Portrait", `00bd43a0` "Headshot". `00bd43f0` (GetHeadshotBuffer) sends "Headshot" when no entry exists. The brief's "exactly Headshot or Portrait" omits TcgPortrait; decide explicitly.
- **Reader 156/3, `00bd4180`:** `00bd31d0` reads two u16 (156, 3). Then u64 guid (+0x10), then string provider (i32 length + bytes, via `00894b10`), then u8 compressed (+0x28), then record `00bd37e0` (+0x30), then image `009538e0` (+0x2100: i32 length + bytes; negative or overflow sets error).
- **Record `00bd37e0`, field order:** i32, i32, u64 guid, i32 model, attachments (`009131c0`), string head, string hair, i32 hair colour, i32 eye colour, string skin tone, string face paint, string model customization, four i32 (`0x2028`–`0x2034`; one is decompiled with a float NaN check, treat as i32, (R)), string provider. This matches the brief's layout.
- **Consumer `00bd4a50`:** calls `00bd4180`. Stores only when the error flag is clear and the cursor reached the end, so trailing bytes store nothing. Inflates via `010ebee0` when compressed. Copies the record into the entry (`00bd27d0`). Stores the image only when its size is nonzero (`00bd2820`/`00bd2870`). Removes the pending entry (`00bd20c0`).
- **`00bd43f0`:** returns the image only when the stored size at +0x2108 is nonzero. An empty image falls through to the rest of the function, which I did not read. So with an empty image the record is kept but GetHeadshotBuffer returns no bytes. The UI fallback is unverified (`LoadDefaultImages`, `HeadshotProxy`).
- **Attachments `009131c0`:** called by AddPc::Read `0091aa10` (callee list) and also by `0091b080`, `00921a10`, `00954ec0`, `00bd37e0`. Reusing `attachments_wire` is plausible (R); byte equality with AddPc not checked.
