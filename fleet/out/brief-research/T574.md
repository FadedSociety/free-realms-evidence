**Risks and corrections:**
1. **The brief's own tests conflict with the timer decision.** Raising `AUTO_REVIVE_MS` to 300 000 breaks `free_revive.rs:194-209` (asserts revive at 15_200) and `:305-317` (asserts a zoning at 17_100). Those two are not "unchanged" tests and need rewriting. The brief's "free_revive.rs tests pass unchanged" applies only to item 2.
2. **The timer premise is mis-anchored.** There is no instance or battle revive timer in `revive.rs`. `REVIVE_TIMER_MS` is the wire value of the overworld window only (see 884/1473/2541), and the overworld dialog ignores it. Keep 10 000 as the wire value. Only `AUTO_REVIVE_MS` changes. Mark the 300 000 as (R) in the `paid_revive` data.
3. **Item 2 has a data-flow gap.** `resume` returns only an `EncounterOutcome`, but the price must reach `spend_coins` in the same commit. `resume` needs to return the price too (for example a new outcome field or a tuple), or Gameplay must keep charging. The wallet can come in as a setter (the `set_player_job` pattern, which must run before every `handle`) or as a new `handle` parameter. The parameter option changes every `handle` caller, including tests.
4. **Hubs.** `encounter.rs` (3158 lines) and `gameplay.rs` (5475) are capped. Item 2 should shrink both: the `gameplay.rs:4742` call goes away and `knockout.rs` shrinks. Adding the timer plumbing in `encounter.rs` must net to zero there.
5. **Serde.** `PaidRevive` and `FieldContent` both use `deny_unknown_fields`. New timer fields need `#[serde(default)]`, so the shipped `field_enemies.json` (`paid_revive` with only `cost` and `source`, lines 3-19) still loads. Timer provenance needs `source` tags that pass `field_rewards::validate_source`.
6. **Item 3.** `spend_coins` returns early for amount 0 with no reply (`inventory.rs:883-885`). Keep that. `coin_balance` must be `pub(crate)` for `coin_shop.rs`.
7. **Gateway tests need the private fixture.** `with_private_content` (`free_revive.rs:528-536`) reads `../lab/reports/...`. The gateway paid tests (`:524`, `:637`) fail without it (unverified whether this is in the known-failing set).
