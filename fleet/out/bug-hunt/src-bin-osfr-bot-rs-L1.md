- **[medium] prototype/osfr-tools/src/bin/osfr-bot.rs:178-214 - `logical_messages` recurses on every nested `[0, 25]` bundle with no depth limit, and each level copies its child (`child.to_vec()` at line 212) while the parent's `message` stays alive, so a hostile gateway can overflow the stack or exhaust memory.**
  - **Failure scenario:** the gateway sends one reliable message of about 3 bytes per nesting level: `[0,25, len, [0,25, len, ... [0,25]]]`. With D = 40,000 levels that is about 120 KB. Each level recurses one frame deeper (line 212) and holds a full copy of its remaining bytes, so peak live memory is about 1.5·D² bytes (about 2.4 GB here), and the thread stack is exhausted at tens of thousands of frames. Either way the bot process dies. The reliable receiver accepts messages up to `max_message` = 16 MB (line 335), so the size is not capped low enough to prevent this.
  - **Reach:** `Bot::service` line 509 `logical_messages(message, &mut messages)` on each reassembled reliable message from `self.receiver.receive` (line 486), for every datagram from `config.gateway` (line 458). The only guard is the `[0,25]` prefix test at line 179, which the nested child satisfies. The server rejects this shape (`gateway.rs:679-680`, "nested message bundles are unsupported"), but the bot does not, and nothing upstream of line 509 checks it.
  - **Fix:** make the bot's bundle split non-recursive and reject nested bundles like the gateway does: after `take` at line 209, return early if `child.starts_with(&[0, 25])`, instead of calling `logical_messages(child.to_vec(), out)`. Equivalently, pass a depth counter and cap it at 1.

- **[low] prototype/osfr-tools/src/bin/osfr-bot.rs:226-231 - `matches_family` also matches the low byte of a two-byte sub-code, so `expect F S` can pass on a different message.**
  - **Failure scenario:** a scripted `expect 36 5` step (sub = 5) matches an inbound family-36 message whose u16 sub at bytes 2..4 is 0x0105. `family_of` gives s = 0x0105, which is not `Some(5)`, but `inner.get(2)` is 0x05 and `u16::from(0x05) == 5`, so the predicate returns true. The step logs `ok expect 36/5` and the script continues on the wrong message.
  - **Reach:** `Step::Expect` at line 636 calls `wait_for(timeout, |m| matches_family(m, family, sub))`. The byte-2 fallback is meant only for one-byte sub families (39/45, per the comment at line 518), but it is applied to every family.
  - **Fix:** apply the byte-2 fallback only when the family is one of the one-byte-sub families, or drop it and require `s == Some(sub)` for sub values above 255.

- **[low] prototype/osfr-tools/src/bin/osfr-bot.rs:451-456 and 456-459 - outside login mode the `service()` drain loop has no budget, so datagrams from any non-gateway peer can keep `service()` (and therefore `pump`/`wait_for` deadlines) from returning.**
