- **[medium] prototype/osfr-tools/src/gameplay.rs:1479 - `learn_consumed_patterns` is wired only to the 42-family inventory branch, and no opcode in that branch ever decreases an item count, so no recipe is learned from any live client action.**
  - **Failure scenario:** a player with a recipe pattern item (for example `recipe_item_definition_id` 2506) sends any 42/x inventory packet. The branch at 5337 clones `before`, calls `handle_inventory`, and then runs `learn_consumed_patterns(&before)` at 5353. The pattern count is unchanged, so `candidates` is empty and no 0x3f/op1 Add is sent. Nothing else in `src` calls `learn_recipe` or inserts into `learned_recipes`, apart from the four opening seeds at 867. Recipes from patterns are therefore never granted in play.
  - **Reach:** client 42/x packet → `gameplay.rs:5337-5339` → `handle_inventory` (5230) → `inventory.rs:1145-1212` `route`. That router handles only opcode 2 (unequip, sets `item_id = 0`), opcode 3 and opcode 8 (equip, which sets `entry.item_id` and never removes from `items`, `inventory.rs:1268`), and `_ => default`. The 35/34 path returns replies without mutation. So the `before`/after comparison at 1479-1498 is always equal. Pattern consumption on the other paths (item bar at `gameplay.rs:5081-5096`, crafting `consume_materials` at `gameplay/crafting.rs:489-508`) does not call `learn_consumed_patterns`. A grep for `learn_recipe` in the whole repo finds only its definition and the call at 1500.
  - **Fix:** run the same `before` snapshot and `learn_consumed_patterns(&before)` around every path that can consume an item (the item-bar use path and the immediate-use path, 42/15, which the router currently drops as a no-op), not only the 42 branch.
