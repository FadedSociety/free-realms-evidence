- **[low] prototype/osfr-tools/src/mining.rs:1517-1535 - `gravity` destroys and tunnels through `TILE_BLOCKER` cells.** The compaction loop skips blockers as sources (`continue` at 1517) but never as destinations, and the refill loop at 1527-1535 writes a queue tile into every row above `target` without checking for a blocker.
  - Failure scenario: a board with height 4, column rows top→bottom `A(400), BLOCK(800), B(400), G(601)`. A client fall of `G` at the bottom row (`collect_fall`, 1554+) leads to `B` moving to row 3, then `A` moving to row 2 past the blocker, then the refill writing queue tiles into rows 1 and 0. The blocker at row 1 is overwritten and no longer exists.
  - Reach: `OnLevelEventMsg 50` → `collect_fall` (1612 `gravity`), and the chain path (758). A client can trigger it, but only on content whose shape contains code `3` or `-800`. The shipped `mining.json` and `mining_spec()` (`blocker_percent: 0`, no `3` codes) never create a blocker, so this is content-only today; the powerup contract at 1854-1865 treats blockers as removable, so the intended semantics are not fully recovered.
  - Fix: in the compaction loop, skip `TILE_BLOCKER` cells as destinations (make `target` step over them), and in the refill loop stop filling at a blocker, or treat blockers as fixed for the whole column pass.

- **[low] prototype/osfr-tools/src/mining.rs:1554-1565 - `collect_fall` is accepted while the run is paused, unlike the sibling handlers.** `OnChainMsg` (697-698) and `OnActionMsg` (784-785) return `"mining is paused"` when `run.paused`, but the fall branch checks only `phase == Playing` (832) and then credits quota and score.

The server removes the tile, increments `collected` and `score`, runs `gravity`, and may reach `LevelComplete`. The timer is frozen during pause (`tick`, 549), so this progress costs no time.
  - Impact is limited: the fall must still be a real bottom goal tile on the server board, each fall removes a tile, and the same progress is reachable after unpausing with no time limit, so I found no item or coin gain. It is an inconsistency in the server's own pause guard.
  - Reach: `handle` (`sub == 14`, `game == -1` or `self.game_id`) → `["OnLevelEventMsg", "50", x, y]` (830) → `collect_fall` (833); no upstream pause check.
  - Fix: add `if run.paused { return Err(invalid("mining is paused")); }` inside the `Playing` branch at 832, matching the chain and action handlers.
