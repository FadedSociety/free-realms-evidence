**[medium] `prototype/osfr-tools/src/restoration/piece_008.rs:1046-1049` - `insufficient_material` ignores bishop square colour, so king+bishop versus king+bishop is declared a dead draw even when the bishops are on opposite colours.**
- Failure scenario: the position `4k3/8/8/8/8/b7/8/1B2K3 w - - 0 1` has a white bishop on b1 (light) and a black bishop on a3 (dark), with no pawns, rooks or queens. `insufficient_material` collects one bishop per side (lines 1019-1024), reaches the final expression at 1046-1049, and returns `true` without comparing colours. `status()` (line 1062) then returns `Status::Draw`. `apply` (line 1127) returns that status to the caller, and `ChessSession::play` (line 1215) ends the game as a draw. Positions with opposite-colour bishops are not dead draws, so this is the wrong result.
- Reach: a client sends a move through `ChessSession::play` -> `Position::apply` (1122-1133) -> `status()` (1052-1066). No upstream check guards the colour test.
- Contract: the doc comment at line 1007 says "opposite-side bishops on one colour", meaning the draw applies only when the bishops share a square colour. The live engine in `src/chess.rs:888-893` does this check (`((a % 8 + a / 8) % 2) == ((b % 8 + b / 8) % 2)`). The test at `tests/piece_008.rs:366-370` covers only K+B v K, so this path is untested.
- Fix: in the final expression, compare square colours when both sides have one bishop. For example, replace lines 1046-1049 with `white_minors.len() == 1 && black_minors.len() == 1 && white_minors[0].kind == Kind::Bishop && black_minors[0].kind == Kind::Bishop && (white_minors[0].square_index() ...)`. Simplest form: carry the square index in the `minors` vectors (push `(square, index)`) and return `(wi % 8 + wi / 8) % 2 == (bi % 8 + bi / 8) % 2`. Note that `white_minors` currently stores `Piece` values with no index, so the index has to be added at lines 1019-1024.
