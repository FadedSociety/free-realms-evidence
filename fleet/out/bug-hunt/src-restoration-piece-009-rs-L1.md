- **[medium] `piece_009.rs:594-600` - the replay check refuses any legal move whose `(side, from, path)` matches an earlier move, even when the position is different, so a legal king move can be refused for the rest of the session.**
  - **Failure scenario:** Red has a king on spot 9 and both sides have other pieces to move. Step 1: Red plays `apply(Red, 9, [13])`, which is accepted (`FORWARD_DOWN` offset (0,1)). Step 2: Black moves. Step 3: Red plays `apply(Red, 13, [9])`, which is accepted (king offset (1,-1) from odd row 3). Step 4: Black moves. Step 5: Red plays `apply(Red, 9, [13])` again. `legal_actions` lists this move because 13 is empty and the king may move forward. `validate` returns `Replayed` at line 599 because `applied` holds the step-1 entry. Once every legal action for the side has been played once before, every submission from that side is refused. `settle()` (line 699) checks only `board.has_action`, not the replay filter, so the session neither ends nor advances.
  - **Reach:** The intended path is `decode_move_payload` (line 729) then `CheckersSession::apply` (line 639) then `validate` (line 584). Nothing in the repo calls `apply` yet, so this is the designed gateway path rather than wired code. The replay check is placed before the turn and piece checks and has no board or turn-index component, so nothing upstream stops it.
  - **Caveat for the refuter:** The behaviour is deliberate. The test `tests/piece_009.rs:342-350` (`late_replays_after_later_turns_are_still_rejected`) asserts that a later repeat is `Replayed`, and the module header marks replay protection as reconstructed policy. The defect is therefore in the policy, not an accidental slip. It still contradicts the rule that `legal_actions` defines legality, and it can wedge a game with no draw rule.
  - **Fix:** Make the replay key the position or turn, not just the action. For example, store the board (or a turn counter) with each `AppliedMove` and only treat an identical `(board, side, from, path)` as a replay. A minimal change is to drop the `applied` scan and rely on the `NotYourTurn` check, which already rejects a true duplicate of the last submission because `current` has changed.
