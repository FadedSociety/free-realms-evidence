- **[medium] session.rs:80 - Multi (opcode 3) child lengths are read as a single byte only, but the reference framing uses a variable-length prefix, so any child of 254 bytes or more is misframed and the whole bundle is rejected.**
  - **Failure scenario:** a peer sends a Multi/Group bundle whose child is 254 bytes or longer. The reference encoder writes that length as `0xFF hi lo` (`refs:Sanctuary/src/Sanctuary.UdpLibrary/Internal/UdpMisc.cs:115-140`, `PutVariableValue`: values `< 254` use one byte, larger values use `FF` plus a big-endian u16 or `FF FF FF` plus u32). The Rust `flatten` reads `0xFF` as length 255 and takes the next 255 bytes as one child. Those bytes start at the high length byte, so the opcode is garbage (`0x00FE`) and the remaining payload is shifted by 2 bytes. For a child that ends the bundle, one trailing byte is left, its value is read as a length, and that length is always `< 2` or `> 0` remaining, so `flatten` returns `Err("invalid SOE control child length")`. `decode_controls` then fails and the gateway drops the entire datagram (`osfr-gateway.rs:1271-1282`). Every reliable packet in that bundle goes unacknowledged, so the peer retransmits forever.
  - **Reach:** the UDP receive path calls `decode_controls(&self.codec, wire)` at `osfr-gateway.rs:1271`, which calls `flatten` (`session.rs:63`). The reference receive loop parses the same Group framing with `GetVariableValue` (`refs:Sanctuary/src/Sanctuary.UdpLibrary/UdpConnection.cs:1145-1165`, `UdpMisc.cs:94-113`), and the reference coalescer emits it (`refs:.../Internal/UdpReliableChannel.cs:1005`). Nothing upstream of `flatten` handles the escape; `codec.decode` returns opcode 3 with the raw payload. The module doc says this is "verified against the supplied SOE implementation", which this contradicts.
  - **Fix:** in `flatten`, replace the one-byte length read with the reference's variable-length decode: if `remaining[0] == 0xFF`, then when `remaining[1..3] == [0xFF, 0xFF]` read a 4-byte big-endian length from the following bytes (after checking they exist), otherwise read a 2-byte big-endian length; else use the single byte. Check bounds before each read and keep the `length < 2` and `length > remaining` checks.
  - **Caveat:** I did not confirm from the client side that a real client actually coalesces a child of 254 bytes or more. The defect is in the framing and is reachable whenever such a child is sent.
