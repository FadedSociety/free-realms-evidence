- **[low] tests/archer_entry_chain.rs:567 two_archers_count_the_same_recruit_independently - the name claims independence, but the second game is never checked at zero before its own talk, and the final asserts repeat the in-loop asserts.**
  - Why it cannot catch a regression: the two `Gameplay` instances are separate objects, so an isolation bug would have to be a shared global. Even then, the only check is that each game reads `[1,0,0,0]` after its own talk. If the first talk leaked into `second` as a count of 1 and `second`'s own talk were then refused as already counted, the `outcome.changed` assert would fail. But a leak that does not change the outcome (for example, a shared non-counted log) passes unnoticed, and the test never asserts the second game's pre-talk state.
  - Fix: assert `counts(&second, PATH) == vec![0,0,0,0]` before the loop talks to `second`, and after `first`'s talk assert that `second` is still zero. Then drop the duplicate post-loop asserts.

- **[low] tests/archer_entry_chain.rs:31 lugabow_offers_path_only_to_archers - the "Oath stays locked" check is a `contains_key` on the quest map, which pins the internal representation rather than the offer behaviour.**
  - Why it cannot catch a regression: the check passes whenever the Oath key is absent from `npc_quests.quests`, whichever way Oath is gated. Conversely, if a future change inserts locked quests into the map as `Locked` (as the load-time repair in `quests.rs:282` already does for definitions), this assert breaks even though Oath is not offered, so it is churn rather than a guard. The same pattern is repeated at lines 158-166.
  - Fix: assert the observable behaviour instead, e.g. `quest_status(&game, OATH)` is not `Offered`/`Active`/`Completed`, or run `assert_no_offer(..., OATH-only target...)` with a 49/1 check for `OATH` on a second Talk.
