  - Why it cannot catch a regression: if `offset_tenths` were changed to accept a float (e.g. `f64` with a `#[serde(alias = "offset")]`, or a custom deserializer that rounds `1.5` to `2`), this input would still error because the key is wrong, so the test stays green while the "integer tenths" guarantee is gone.

- **[medium] prototype/osfr-tools/tests/client_objectives.rs:202-240 `only_open_goals_of_the_character_own_active_quest_are_registered` - the name claims "open goals" are filtered, but every quest has exactly one objective, so the ordered-quest gating is never exercised.** The helper `quest()` sets `ordered: true`, and `current_objectives` (quest_engine.rs:1321-1337) limits an ordered quest to its first unfinished step; that rule is the "open goal" part of the name.   - Why it cannot catch a regression: a change that makes `open_client_objectives` return every `ClientReported` objective of an active ordered quest (ignoring step order) still passes, because the only quest here has one objective.
