- **[medium] prototype/osfr-tools/tests/gateway.rs:298 an_application_child_after_a_jump_drops_the_staged_relay - the test never confirms the jump inside the bundle was staged before the application child arrived, so the final `is_none()` can pass without the drop logic running.**
  - Why it cannot catch a regression: the only staging check (line 303) comes from a separate single-jump `handle` call. If the bundled `jump(1, [5.0,2.0,3.0], 4.5)` at line 309 were never staged (for example the impulse were dropped during bundle splitting, or `jump_relay` were never set on the bundle path), the relay would be `None` at line 315 and the test would still pass. The `impulse = None` at gateway.rs:1638 is therefore never shown to be the cause of the clear.
  - Fix: insert a bundle-only probe. Send `bundle(&[jump(...)])` alone, assert `take_jump_relay().is_some()`, then send the jump+application bundle and assert `take_jump_relay().is_none()`. Alternatively, assert that the jump-only bundle's staged body differs from the post-application state.

- **[medium] prototype/osfr-tools/tests/gateway.rs:154 typed_startup_builder_serializes_session_position_and_preserves_tail - for every reply except index 7 the expected bytes come from the same `startup.build_packet` / `startup.build_zone` the gateway calls, so the assertion restates the computation.**
  - Why it cannot catch a regression: a change inside `StartupSnapshot::build_packet` or `build_zone`, such as a wrong opcode, a wrong GUID substitution, or a truncated body, changes both sides equally and the test still passes. Only the ignored byte-for-byte oracle at line 131 checks those bytes against an independent source, and it does not run by default. Index 7 is only checked as a round trip through the same typed module, which is weaker still.
  - Fix: add a non-circular canary to the default run. For example, check the GUID bytes at a fixed offset in each non-login reply equal `state.guid.to_le_bytes()`, check the zone-packet zone id field equals `state.zone_id`, and check the packet opcodes equal the constants used in `synthetic_startup_sequence_has_the_expected_phase_order_and_lengths`. Each of these fails if the builder's content changes.

- **[low] prototype/osfr-tools/tests/gateway.rs:510 actual_original_client_capture_when_explicitly_configured - `zip` silently truncates to the shorter of `replies[..46]` and the analysis's server-to-client list, so a capture with fewer than 46 recorded server messages is compared against fewer templates and still passes.**
  - Why it cannot catch a regression: if the server-to-client array shrinks, or the gateway stops emitting some templates, the loop checks only the overlap. The ignored oracle also never asserts the array length, so a short capture is never noticed. This test is ignored unless the private reference is set, so this matters when it does run.
  - Fix: before the loop, assert `analysis["directions"]["server-to-client"]["messages"].as_array().unwrap().len() >= 46` (or `== 46`), and assert `replies.len() >= 46` before slicing.
