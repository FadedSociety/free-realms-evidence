The starter-weapon tests and the shipped-row test check real outputs (the activation path, `equipped_weapon_matches`, the 32/7 hits) against constants, so they are not tautological. Two findings:

- **[medium] tests/job_basic_attacks.rs:303 `unequipped_basic_is_refused_without_combat_change` - the "unarmed" precondition is never checked, and there is no armed control, so the `!hit` assertion can pass for any reason.**
  - Why it cannot catch a regression: if the unequip command (42/2 with `[7, 2]`, line 311) is a silent no-op, the job keeps its weapon and the basic would hit, so `!hit` fails. But if the basic attack is broken in general (the 36/10 path never produces a 32/7 hit, the target is not targetable, or the encounter never starts), `!hit` still passes and the state comparison at 318 still passes because nothing changed. Nothing shows that the same basic attack lands when armed, so the refusal is not attributable to the unarmed state.
  - Fix: before line 311, assert that `equipped_weapon`-style slot 7 for profile 2 is empty (`item_id == 0`, or `equipment_matches` false). Also add a positive control first: a basic attack from the armed state must produce `hit(...)` and change the enemy health. Then the unarmed attack is refused only in the state where the armed control succeeds.

- **[medium] tests/job_basic_attacks.rs:271 `clothed_warrior_without_a_weapon_gets_the_starter_cudgel` - the "without a weapon" precondition is never established, so the test cannot tell whether the cudgel came from the activation at line 298.**
  - Why it cannot catch a regression: `fresh_game` (line 142) already activates job 32, which grants the starter cudgel. The unequip at line 274 (42/2, `[7, 32]`) is never verified to have removed it. If that unequip is a no-op, or if activation never re-grants the weapon, the final `equipped_weapon(..., 29963)` at line 300 still passes, because the weapon is already there from `fresh_game`. The test's name claims the cudgel is granted to a weaponless warrior, but nothing checks that the slot was empty before the re-activation.
  - Fix: after line 274, assert slot 7 of profile 32 has `item_id == 0` (or that `equipped_weapon_matches(..., 32, Some(17))` is false). Only then does the test prove that line 298 grants the cudgel. Optionally, assert that the item instance id from `fresh_game`'s grant is absent from `state().inventory.equipment` after the unequip.
