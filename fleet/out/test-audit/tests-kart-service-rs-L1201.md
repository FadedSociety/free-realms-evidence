- **[medium] tests/kart_service.rs:1461 legit_ordered_race_finishes_and_offers_the_reward_once - the only assertion tied to the comment ("every accepted gate reported the local racer's progress block") is `observations() == 0`, which is trivially true for this path.**
  Why it cannot catch a regression: `observations` is incremented only by the pickup claim (`src/kart_service.rs:1907`) and the server-data frame (`:2023`), never by `claim_gate`. Any change to gate handling, including one that starts emitting or dropping progress blocks on each accepted gate, leaves this assertion at 0 and passes. The comment describes behaviour the test does not check.
  Fix: delete the comment and the `observations()` line, or replace it with an assertion on what the comment says (e.g. the replies returned by each accepted `gate_claim` in `drive_lap`, or a check that gate claims leave `observations()` unchanged when they are the only frames sent).

- **[low] tests/kart_service.rs:2178 curtain_validator_rejects_folded_sliver_concave_and_bow_tie - the doc says each vector "fails exactly one rule, so a regression in that rule shows up," but every case asserts only `GateCurtainGeometry { gate: 0, leaf: 0 }`, which does not say which rule fired.**
  Why it cannot catch a regression: if the validator is changed so the folded or bow-tie vector is rejected by a different rule (or by a rule that was supposed to pass the shape), this still passes. A regression that makes the sliver pass on another rule would also go unnoticed, because only the error variant is compared.
  Fix: assert the rule that is meant to fire, e.g. add a `reason`/`rule` field to `GateCurtainGeometry` and compare it per vector, or at minimum check the rejection with a second vector that passes all rules but one. Otherwise change the doc to say only that each shape is rejected.

- **[low] tests/kart_service.rs:2333-2334 flush_spends_banked_credit_and_cannot_mint_time - the doc says "the first burst claim is paid from savings," but the first claim is paid from elapsed time.**
  Why it matters: at 2.759 s × 60 m/s the time allowance is 165.5 m, so the first 60 m claim draws on time and banks 105.5 m. Only the second claim (16 ms later, below `MIN_CLAIM_DELTA_MS`) is paid from the bank. The assertions are correct, but the doc misstates the mechanism the test is meant to exercise, which could mislead a later reader into weakening the rate-floor path.
  Fix: reword the doc to "the second burst claim, inside the rate floor, is paid from the bank left by the first."
