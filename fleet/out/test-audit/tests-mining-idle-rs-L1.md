Two findings:

- **[medium] prototype/osfr-tools/tests/mining_idle.rs:215 idle_ack_outside_the_board_is_refused_atomically - the out-of-board coordinate is listed first, so the test never sees a partial application.**
  - Why it cannot catch a regression: `handle` parses the whole list and then, in the `OnIdleMsg` arm (`mining.rs:801-811`), loops `for (x, y) in points`. With `0,0` first, the bad point is hit on the very first iteration, so nothing has been written yet. A change that writes each valid tile in place as it goes (for example, mutating `self.state` directly instead of `next`, or dropping the `next` clone) and then errors on a later bad point would still pass, because this input never reaches a later point. The only thing the test really checks is that the first point is refused.
  - Fix: put the bad coordinate last, e.g. `"OnIdleMsg\t4,4,0,0,"`. Then a partial write of `4,4` (which starts busy because `state_with` marks it) would change `engine.state()` and the `assert_eq!(engine.state(), &before, ...)` would fail. Optionally add a second case with a valid tile and a bad tile in the middle.

- **[low] prototype/osfr-tools/tests/mining_idle.rs:268 idle_acks_keep_their_non_playing_behaviour - the name says "non-playing", but the second half is a Playing-phase run.**
  - Why it cannot catch a regression: the first half covers `Type8Phase::Won` only. The second half (`Playing` with `paused: true`, lines 286-295) is a live Playing run, so the name does not match what is being pinned. The test still does exercise paused play, but a reader looking for coverage of the other non-playing phases (Offered, Launched, Connected, LevelOffered, Lost) will find none under this name.
  - Fix: rename to something like `idle_acks_follow_terminal_and_paused_rules`, or add the other non-Playing phases to the first half, looping over `[Offered, Launched, Connected, LevelOffered, Won, Lost]` and asserting `engine.state() == &before` for each.
