- **[medium] tests/npc_greetings_sanctuary.rs:496 `a_missing_or_zero_greeting_still_falls_back` - the name promises a zero greeting case, but no zero-valued greeting is ever loaded or exercised; only a missing-field row (`BLANK`, 9500000443) is tested.**
  - Why it cannot catch a regression: if the loader or `dialogue_context` started turning `greeting_string_id: 0` into a fabricated `Some(0)` or a name id, the test would still pass, because its only zero-related checks are on the constant table (`assert_ne!(row.greeting, 0)` at 548, which duplicates the check at 266 and never touches `dialogue_context`).   - Fix: add a fixture/synthetic record in a temp content dir with `"greeting_string_id": 0` and assert `service_talk_body` is `None` and the 26/3 body is `0`; or rename the test to "a missing greeting falls back" to match what it checks.

- **[medium] tests/npc_greetings_sanctuary.rs:553 `every_edited_row_is_drawable_and_no_other_row_changed` - "no other row changed" compares only the `greeting_string_id` and its `field_sources` (lines 601-635), not the rest of the row, and only for `sanctuary.json` plus three Cobblestone rows.**
  - Why it cannot catch a regression: a change to `name_string_id`, `model_id`, `position` or any other field on any non-edited sanctuary row passes, and a stray greeting added to `farnum_farmstead.json` or another NPC file is never looked at, since the loop is scoped to `npc_records("sanctuary.json")`.
  - Fix: snapshot the full non-greeting record for every non-edited row (e.g. compare `record` minus `greeting_string_id`/`field_sources` against a stored hash or fixture), and loop over all `npcs/*.json` files asserting that the only greeting bindings are the pre-existing, later and edited sets.

- **[low] tests/npc_greetings_sanctuary.rs:293-306 `the_new_rows_have_nonzero_greetings_and_real_sources` - the source-evidence needles are bare substrings, so a wrong id or line still matches a longer correct one.**
  - Why it cannot catch a regression: `Global.Text.21534` matches evidence that cites `Global.Text.215340`, `hash 81168942` matches `hash 811689420`, and `line 95` matches `line 955` (the Sanctuary guide line 95 is shared by two rows and an edit to 955 would still pass).   - Fix: match with a delimiter, e.g. check the evidence contains `"{needle}"` followed by a non-digit (or split on non-digit characters and compare tokens), so `Global.Text.21534` cannot match `...215340`.
