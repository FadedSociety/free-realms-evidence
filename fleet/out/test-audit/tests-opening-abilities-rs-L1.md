- **[medium] tests/opening_abilities.rs:257 full_roster_preserves_campaigns_with_only_some_basic_attacks - the name says the full roster survives a campaign with only some basic attacks, but the profile-32 checks cannot see the roster.**
  - Why it cannot catch a regression: `job_slot` returns `None` whenever `basics` has no entry for the profile (`src/opening_abilities.rs:280`). Profile 32 has no basic in `Fixture::new()` (only 43 does), so `assert!(abilities.job_slot(32, 1, 20).is_none())` at line 265 passes even if the roster for 32 is dropped entirely. The `bar.len()==1` and all-zero check at 266-268 also hold for any roster. Only the profile-43 assertions at 262-264 test the roster, so a regression that drops the roster for profiles that do have a basic is caught, but nothing checks a profile whose roster should be present while its basic is absent.
  - Fix: add a second basic (for example profile 32) to the fixture, then assert `job_slot(32, 1, 1).is_some()` and `job_slot(32, 4, 15).is_some()`. Keep the `none` check only as a companion to a positive assertion.

- **[medium] tests/opening_abilities.rs:329 shipped_job_abilities_file_loads_through_the_real_loader - the test only unwraps `load_job_abilities`, so an empty or silently ignored roster still passes.**
  - Why it cannot catch a regression: `load_job_abilities` accepts a file with an empty `jobs` array (the loop at `src/opening_abilities.rs:234` simply does nothing), and the test asserts nothing afterwards. A change that loads zero jobs from the shipped file, or stops reading the file, still passes.
  - Fix: after loading, assert content, for example `abilities.job_slot(43, 1, 1).is_some()`, `abilities.job_slot(11, 5, 15).is_some()`, and `abilities.job_bar(35, 20).iter().flatten().count() == 5`. The size-cap purpose (the 64 KiB regression) stays covered by the unwrap.
