Two findings:

- **[medium] prototype/osfr-tools/tests/piece_048.rs:469 unowned_and_unavailable_items_are_rejected_without_state_change - the name promises no state change, but the body never snapshots state and its own first assertion (line 488) expects a binding to be pruned, which is a state change.**
- **Why it cannot catch a regression:** `assign` calls `validate()` then `reconcile()` before any rejection path (src piece_048.rs:663-664), so a change that drops or keeps arbitrary other bindings on a rejected request still passes as long as the final `is_empty()` holds. The zero-stack half (lines 490-503) runs against a state that is already empty, so it cannot detect a write either. A rejected request that wrote a binding into an unrelated slot and then the test's `is_empty()` would fail, but a rejected request that mutates a valid existing binding (for example a `definition_id` rewrite or a slot overwrite) is never caught because no before/after comparison exists.
- **Fix:** rename to match what is tested (e.g. `unowned_items_are_rejected_and_stale_bindings_are_pruned`), or add a valid live binding before the rejected requests, clone `state.bindings()` (or `serde_json::to_string(&state)`) before each rejected `assign`, and assert the rejected call leaves the surviving bindings byte-identical. Make the zero-stack case run against a state that holds a valid binding so it can show no change.

- **[low] prototype/osfr-tools/tests/piece_048.rs:151 assign_request_rejects_lengths_and_families_outside_the_original_form - the name says unknown families are rejected, but the final case (lines 166-171) asserts `other_sub` returns `Ok(AssignParse::OtherSubOpcode)`, not an error.**
- **Why it cannot catch a regression:** a change that turned unknown sub-opcodes into errors (or into requests) would still break only that last assert, and the name describes a rejection the test never checks as one. A reader trusting the name would believe sub-opcode rejection is covered when it is classification-only.
- **Fix:** rename to cover "sub-opcodes classified as other" or split the sub-opcode case into its own test named for `OtherSubOpcode`, and keep the error-only cases (short, long, wrong family, 2-byte) in the rejection test.
