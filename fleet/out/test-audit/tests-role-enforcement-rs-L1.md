- **[high] role_enforcement.rs:108-110 verified_owner_roles_persist_and_online_demotion_is_immediate - the "store lost, fail closed" check cannot distinguish fail-closed from the cached role, because the session was already demoted to Player at line 97-102.**
  - Why it cannot catch a regression: at line 102 `gateway.role()` is already `Player`. If `refresh_role` stopped reloading on a missing file and simply kept the cached role, the session would still be Player and `realm here` would still be denied. A change that caches Admin rights past store loss, or that defaults to Admin on read error, would not be exercised here at all, since the role is never Admin at the moment the file is removed.
  - Fix: before line 109, re-establish an Admin binding (e.g. `store.set_account_role_offline(2, Admin)` + save, then `gateway.bind_account_role(&path, 2)` and assert `gateway.role() == Admin`), then remove the file and assert `gateway.role() == Player` and that a gated command such as `realm god` returns `dev_command_denials == 1`.
